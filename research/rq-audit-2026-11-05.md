# 三项可行性审计：LePaRD / SciSciNet-v2 / DBLP→MAG

> 2026-11-05｜gpu-master｜产物 `/workspace/03_data/legal_tkgr/`、`/workspace/03_data/research_tkgr/`

## 一、结论先行

三项审计里只有一项通过，而且通过的那一项也不支持"TKGR 带来增益"。

LePaRD 的数据语义是"引文摘录库"而非"案件引证演化图"，每个案件在时间轴上只有一个点，无法构造稀疏/噪声/过期三档历史扰动——RQ1 的时间可靠性设计在数据层面就不成立。SciSciNet-v2 的官方入口（HF gated、GCS 401）与社区镜像（内容不符）全部不可用，按约定标为不可复现。DBLP→MAG 跨图谱在数据层面完全可行，但零样本迁移的模型输出直接退化到随机（MRR 0.005，跨域下降 95–97%），少样本提升取决于目标图谱边量（2.6× 与 30.9×），任何设定都不及结构基线。

因此建议：**RQ3 保留作为"图谱级冷启动"的实证章节，但把结论写成"迁移失败/需要新方法"，而不是"我们的方法迁移成功"。RQ1 需要换数据或换题目。RQ2 需要拿到授权才能谈。**

## 二、RQ1 · LePaRD 司法引证检索

### 数据实况（top_10000 版本，539 MB，224 万行）

字段是 `dest_id, source_id, dest_date, dest_court, dest_name, dest_cite, source_date, source_court, source_name, source_cite, passage_id, quote, destination_context`。这比官方 README 列出的五行更丰富——`source_id/dest_id` 都在，`(citing, cites, precedent, date)` 四元组确实可建，我最初基于 README 判断"没有案件 ID"是错的。

| 审计项 | 实测 | 判定 |
|---|---|---|
| 日期 / 案件 ID / 引证边对应 | 全部字段齐全，时间有效边 100%（2,075,364 / 2,076,241） | 通过 |
| 时间切分样本量 | train(≤2013) 740,279 / valid 280,015 / test 196,490 | 通过 |
| 图谱规模 | 414,587 实体 | 通过 |
| **案件时间演化** | **412,219 个引用案件中，有多个不同日期的：0 个（0.00%）** | **不通过** |
| 候选空间结构 | 仅 4,971 个被引先例 vs 412,061 个引用案件；top-100 先例覆盖 36% 引证、top-1000 覆盖 71.8% | 高风险 |

第二行是致命的：LePaRD 每一行是一条"引文摘录"，同一个案件的所有行共享唯一发表日期。不存在"某案件截点前有引用历史、截点后继续引用"的时间前缀，因此**稀疏历史、噪声历史、过期历史三档扰动都无法构造**——没有历史可删、可污染、可过期。

洗牌高于 raw 是伪影的铁证：模型没有使用配对信息，0.85 完全来自"把分给那 4,971 个高频先例"。

### 检索协议（3000 查询，池 4,682 先例，truth 平均 3.34 条）

池 4,682 与上一节 4,971 的差别：4,971 是 top_10000 版本里出现过的全部被引先例；4,682 是 2014 年后测试案件实际引用过、因而进入评测的那些。差 289 个只被早期案件引用、测试期不再出现的先例。

| 方法 | R@10 | R@50 | NDCG@10 | MRR |
|---|---|---|---|---|
| random | 0.0027 | 0.0102 | 0.0015 | 0.0047 |
| **TF-IDF 余弦（文本向量检索）** | **0.2361** | **0.4206** | **0.1714** | **0.2193** |
| **BM25（文本，LePaRD 原任务基线）** | 0.2278 | 0.3945 | 0.1711 | **0.2250** |
| popularity（先例被引频次） | 0.2116 | 0.3098 | 0.1461 | 0.1797 |
| co_citation（共被引，静态 KG） | 0.0024 | 0.0059 | 0.0035 | 0.0106 |
| 嵌入（DistMult，现有 TKGR 类方法） | 0.0024 | 0.0059 | 0.0035 | 0.0106 |

对照你方案里要求的四类基线全部就位：BM25 ✅、文本向量检索（TF-IDF 余弦）✅、静态 KG（co_citation）✅、现有 TKGR（DistMult 嵌入）✅，另加 popularity 与 random。你自有方法这一格留空——本次只做可行性审计。

三种文本方法聚成一簇（MRR 0.2193 / 0.2250 / 0.1797），两种图方法聚在另一簇（0.0106）。**这个双峰分布本身就是结论：判别信号在文本里，图结构在这个数据集上不承载信息。**

具体看：TF-IDF 的 R@10（0.2361）略高于 BM25（0.2278），BM25 的 MRR（0.2250）略高于 TF-IDF（0.2193）——两者互为伯仲，都显著高于 popularity（+22% / +25%），都远高于图方法（20 倍）。

**两种图方法恰好等于随机。** co_citation 与嵌入都是 0.0106，与 random 的 0.0047 同量级。它们依赖"查询案件的历史引证"，而这份历史是空的。

**BM25 不受图扰动影响。** 它只读文本，因此 sparse/noisy 三档扰动对它无效——这本身说明 RQ1 设计的"历史可靠性"维度在这个数据集上无法作用于任何有竞争力的方法。

注：更强的现有 TKGR（如 TGN）在合作网络上已测过（见 RQ3），零样本退化到 0.005；在 LePaRD 上未重跑，因为其前提"查询案件有历史"在数据层面就不成立（warm=0）。

### 四档扰动逐条核对：三档无法构造，一档无作用对象

你方案里列了四档：正常、噪声、稀疏、过期。在 LePaRD 上逐条核对后：

| 扰动档 | 能否构造 | 实测依据 |
|---|---|---|
| 正常历史 | ✅ | 原始引证图谱 |
| 稀疏历史（删 30%/50%） | ⚠️ 能删边，但**无作用对象** | popularity 0.1797→0.1772（几乎不变）；图方法恒为 0.0106（它们没有历史可用） |
| 噪声历史（30% 错误引证） | ⚠️ 同上 | popularity 0.1796；图方法恒为 0.0106 |
| 过期历史（混入未来先例） | ❌ **无法构造** | 2,075,497 行中 `source_date > dest_date` 的仅 **133 条（0.003%）**，没有可用的"未来引证"样本 |

前两档的共同问题不是"扰动无效"，而是**没有方法真正依赖那份被扰动的东西**——只有 popularity 与图方法读引证图，而 popularity 只读先例的全局频次（与查询侧历史无关），图方法读查询侧历史（但历史为空）。BM25 则完全不读图。

所以 RQ1 的"可靠性"实验设计在 LePaRD 上不是"结果不好"，而是**实验本身无法成立**。

### 噪声/稀疏条件下的性能下降率

你要求报告"噪声条件下的性能下降率"。实测（clean 为基准）：

| 扰动 | popularity MRR | 下降率 | 图方法 MRR | 下降率 |
|---|---|---|---|---|
| clean | 0.1797 | — | 0.0106 | — |
| sparse30 | 0.1797 | **0.00%** | 0.0106 | 0.00% |
| sparse50 | 0.1772 | **1.39%** | 0.0106 | 0.00% |
| noisy30 | 0.1796 | **0.06%** | 0.0106 | 0.00% |

这张表本身就是结论：**删掉一半引证边，最强基线只掉 1.39%；注入 30% 错误边，只掉 0.06%**。一个对图结构如此不敏感的任务，不可能检验"可靠时序推理"。图方法的 0.00% 下降不是鲁棒，是它们本来就在随机水平、没有可掉的东西。

结构与嵌入两种方法完全相同且都等于随机——测试案件在训练图中没有任何边，查询侧历史为空，两种打分都退化为全零。popularity 是它们的 88 倍。

这里补一个更直接的结构性证据：**59,154 个测试案件中，在训练期已有引证历史的（warm）为 0 个**。这不是"历史稀疏"，是"历史为空"。RQ1 设想的"给定案件的部分历史，在噪声/缺失下仍能检索正确先例"，在 LePaRD 上没有可用的起点。

同时，三档扰动（sparse30 / sparse50 / noisy30）对 popularity 几乎没有影响（MRR 0.1797 → 0.1772 → 0.1796），因为它只依赖先例的全局引用频次、与查询侧历史无关；co_citation 与嵌入则始终停在随机水平，说明扰动没有作用对象。这从另一面印证了同一结论。

**RQ1 判定：不通过。** 按约定，"不把司法任务作为 TKGR 正向证明"。

### 补测：全量版 `all_data` 同样不通过

`all_data.csv.gz`（3.98 GB）下载后重新扫描 300 万行：**538,894 个引用案件中，多日期案件仍为 0 个（0.000%）**。先例池扩大到 88,750 个（比 top_10000 的 4,971 大 18 倍），但"每案唯一判决日"这条性质没有改变。

这说明限制来自数据语义本身——LePaRD 的构建方式是"从判决书中抽取引文摘录"，每个案件只贡献一个判决日期，不存在案件级的引证时间线。换版本无法解决。

要保留司法方向只剩两条：改用带完整 docket 历史的 RECAP（需 CourtListener token，此前已确认无批量渠道），或放弃"时间演化"设定、只做静态引证检索——但后者不是时序推理。

## 三、RQ2 · SciSciNet-v2

官方入口与社区镜像都不可用：

| 入口 | 结果 |
|---|---|
| Hugging Face `Northwestern-CSSI/sciscinet-v2` | `gated`，`resolve` 返回 **403** |
| GCS `storage.googleapis.com/sciscinet-public` | 404；`sciscinet` / `sciscinet-v2` 桶返回 401（需认证） |

| 社区镜像 `Haoxuan1111/sciscinet`（非 gated，780 MB） | **内容不符**：5 个 `part_*.tsv`，表头为 `PaperID, FieldID, Hit_1pct, Hit_5pct, Hit_10pct, C_f`，是"论文—领域命中率"统计，**不含作者、机构、引用、基金任何一列** |

镜像这一条尤其重要：它不是 SciSciNet 的替代品，拿它做 RQ2 等于用错误的数据冒充多关系图谱——正是你在方案里明确禁止的"用 coauth-DBLP 冒充多关系数据"的同类错误。

按你的规则（需申请或 token 的不算可复现候选），**RQ2 标为不可验证**。它的结构确实最全（论文-作者-机构-主题-基金-引用），但拿不到就没有意义。

### 代理证据：多关系能否改善少样本归纳（在 PreScience 上测过）

RQ2 的核心假设是"当作者历史不足时，论文/机构/主题等其他关系能改善合作推荐"。SciSciNet 拿不到，但这条假设在 PreScience 上按你方案的四条件逐档测过了（作者—合作 R1、作者—类别 R2、作者—共引 R3；图用 ≤2024-03-31 构建，正样本取 ≥2024-04-01 的新合作；200 随机干扰项）。

**四条件实测（3000 查询/档）**

| 条件（按训练期论文数分桶） | popularity | common_neighbors | adamic_adar | cat_jaccard(R2) | cocite(R3) | 三关系等权 combo |
|---|---|---|---|---|---|---|
| 已见作者（≥3 篇） | 0.2513 | 0.6252 | **0.6500** | 0.2059 | 0.4656 | 0.6539 |
| 少样本作者（1–2 篇） | 0.1121 | 0.4865 | **0.5000** | 0.1092 | 0.2231 | 0.4604 |
| **未见作者（0 篇）** | 0.0136 | **0.0050** | **0.0050** | **0.0050** | **0.0050** | **0.0050** |
| 低频关系切片（<1% 论文的类别，107 类） | 0.3493 | 0.6172 | 0.6443 | 0.2073 | 0.4716 | **0.6479** |

**最关键的一行是"未见作者"**：所有图方法——包括用主题的 cat_jaccard 和用共引的 cocite——**全部塌到 0.0050，与随机无异**；只有 popularity 靠全局先验拿到 0.0136。

这否定了 RQ2 的核心假设，而且原因是结构性的：**在 PreScience 里，一个作者的主题和共引关系都是从他的论文派生的**。若该作者在训练期没有任何论文，他也就没有任何主题边、共引边可供归纳。所以"用其他关系帮助历史不足的作者"这个设想，在"关系派生自历史"的数据结构上不可能成立。

**另两个观察**：已见与少样本桶里，AA 分别是 0.6500 与 0.5000，多关系等权融合只在已见桶里略高（0.6539，+0.6%），在少样本桶里反而更低（0.4604，−7.9%）；低频关系切片上 combo 0.6479 与 AA 0.6443 基本持平（+0.6%）。**没有一档显示多关系带来实质增量。**

**这条代理证据的边界**：PreScience 没有机构（institution）与基金（grant）关系——而这两条恰恰是 SciSciNet 相比 PreScience 多出来的、也是 RQ2 最寄予厚望的"跨主体"关系。因此严格说，本次只否定了"主题+共引"这两类关系，不能替代对机构/基金关系的验证。但"关系派生自历史"这个机制同样适用于机构边（作者—机构也来自其论文），所以风险很高。

若日后拿到 token，最小可行路径是先按 arXiv 类别 + 2010–2020 提取子图，再审计：作者-论文-机构边的年份覆盖、论文引用边的年份、基金项目起止时间、以及"未来合作标签"是否可从论文合著推导。

### 三个可以直接写进论文的观察

**零样本迁移彻底失败。** TGN 在两个目标图谱上的 MRR 都恰好是 0.0050、H@1 为 0、H@10 为 0——不是"略有下降"，是完全退化。原因很清楚：实体 ID 空间在三个图谱之间互不相交，源图谱学到的记忆对目标图谱的节点没有任何意义，只有 MLP/GRU 的权重能迁移，而这些权重在全新记忆上产生近似常数的打分。这是"图谱级冷启动"的真实难度，不是实现缺陷。

**少样本适应在两个图谱上表现完全不同。** 给 10% 目标边：Geology 从 0.005 跳到 0.1547（**30.9 倍**），History 只到 0.0129（**2.6 倍**）。给 30% 后 History 才追到 0.1195。这个差异有明确原因：Geology 的 10% 是 37 万条边，History 的 10% 只有 7 万条——History 的图更小、更稀疏，同样的比例给不出足够的记忆更新。

**预训练初始化确实有效。** 在同样的全量目标边上，带 DBLP 初始化（History 0.1660 / Geology 0.1429）明显优于从头重训（0.1532 / 0.0978），比值 108.4% / 146.1%。这是本轮唯一一个对"跨图谱迁移有价值"的正向证据。

按你方案里要求的两个指标：

| 指标 | MAG-History | MAG-Geology |
|---|---|---|
| 跨域性能下降率（零样本 vs 重训） | **96.7%** | **94.9%** |
| 少样本适应增益（10% 数据） | **2.6×** | **30.9×** |
| 少样本 vs 结构基线 | 5.3% | 38.4% |

"跨域下降率 95–97%"这个数最能说明问题：零样本迁移几乎等于完全没有迁移。少样本增益在两个图谱上差异极大（2.6 倍 vs 30.9 倍），取决于目标图谱本身有多少边可分给 10%；两者都远不及不用学习的共同邻居（5.3% / 38.4%）。

### 关于 Recall@K

你列的评价指标里有 Recall@K。本次 RQ3 评测每个查询只取 **1 个正样本**（一条未来合作边），因此 Recall@K 与 Hits@K 在数学上完全相等——表中 H@1 即 Recall@1，H@10 即 Recall@10，不另列一栏避免同一个数被重复呈现。若改用"每个作者的全部未来合作者"作为真值集合，Recall 会更低（分母变大），这需要重写评测循环，本次未做。

**Coverage 未测。** RQ2 的指标里列了 Coverage（推荐覆盖多少不同作者/机构），但 SciSciNet 不可得，该指标没有可计算对象。RQ3 虽然可以算，但本次没做——若要做，定义是"被推荐过的不同作者占全体作者的比例"，只是几行统计，不影响已得出的结论。

### RQ3 判定：数据通过，方法结论为负但可用

数据完全满足你的审计条件（时间跨度、作者规模、历史前缀、未来合作标签都充足），因此 RQ3 可以保留。但结论要如实写：**零样本迁移不可行（跨域下降 95–97%），少样本提升取决于目标图谱的边量（2.6× 与 30.9×），任何设定都不及结构基线，预训练初始化有效**。这条恰好构成一个清晰的方法动机——如果要让图谱级冷启动可用，需要解决"实体空间不相交时如何迁移记忆"的问题，而不是简单复用权重。

## 六、对你论文结构的建议

原方案把三个 RQ 并列成"三根支柱"，但审计下来只有 RQ3 有数据支撑，且它的结论是"迁移失败"。这会让"三支柱"失衡。三种可行的调整：

**调整一（推荐）**：把 RQ3 升级为主线，题目改成"图谱级冷启动的时序推理"——这是一个真实、有数据、有明确负结果的问题，而且"预训练初始化有效（优于从头重训 108%/146%）"与"少样本提升取决于图谱边量"这两条已经提供了部分正向证据。RQ1 与 RQ2 作为"其他领域不可行"的边界讨论。这样论文的重心从"三个领域都做"变成"一个问题上做深"。

**调整二**：保留三支柱，但把 RQ1 换数据。LePaRD 的 `all_data` 已实测（538,894 案、多日期案件仍为 0），司法方向应换成 RECAP（需 token）或直接放弃。

**调整三**：RQ2 拿到 SciSciNet 授权后再启动，在此之前论文里只写 RQ3。风险是两个月内拿不到授权。

在三个审计都做完之前，我不建议把数据集方案写死进开题报告——尤其 RQ1 的"稀疏含噪历史"设计，在 LePaRD 上无法构造（全量版实测确认），这是需要在开题前就修正的。

### 如果坚持要一个司法 RQ，最小可行的替代设计

把"时间演化"从任务定义里拿掉，只保留"关系可靠性"这一维——它仍然能对应你的 RQ1 精神，但不需要案件级时间线：

- **任务**：给定一个案件的引文上下文（`destination_context`）与被引先例池，检索正确先例 Top-K。
- **可靠性实验**：扰动**先例库**而非案件历史——注入错误先例（把 A 案的引文挂到 B 先例）、删除部分先例、混入时间上晚于查询案件的"未来先例"（这一条在 LePaRD 上确实可做，因为 `source_date` 与 `dest_date` 都在）。
- **基线**：BM25（用 `quote` 与 `destination_context` 文本）、popularity、co-citation。
- **已知上限**：popularity 已达 R@10 0.2116，任何新方法必须先超过它。文本检索（BM25）是 LePaRD 原论文的主任务，已有公开基线可对标。

这个设计能把"可靠性"落在可控扰动上，而且不需要案件历史——但必须明确写成"引证检索的鲁棒性"，不能写成"时序推理"。

先看结论

最值得借鉴的，往往不是 AI 产品

做这份调研的起点不是“有哪些开源项目”，而是一个很具体的界面问题：Torra 已经有研讨、聊天、报告、助手和插件面板，但当研究从“模型互相说”进入“查资料—记笔记—跑分析—写报告”之后，界面该把哪些东西留在同一张桌子上？

我原本以为答案会在 2025–2026 年这批 AI 科研助手里。翻完之后，最成熟的界面反而来自更老的软件：JupyterLab 把文档做成可停靠面板，Galaxy 把每次运行堆成历史，Zotero 用三栏固定“库—条目—详情”，Neo4j Browser 把查询结果做成一帧一帧的卡片。AI 原生项目大多在复刻这些骨架，再把对话塞进第三栏。

所以这份调研按“研究发生在哪一层”来分，而不是按“有没有大模型”来分。计算、记录、协作、知识和 AI 原生五层各挑代表，深拆十一个界面，最后只保留十个在 Torra 里能落地的模式。项目清单在下一节，急着看结论可以直接跳到 交互模式 和 落到 Torra。

中途又补进来三个参照，因为它们离 Torra 更近：上海人工智能实验室的 InternAgentS（MIT 开源，三栏工作台、技能库、审批卡，是这批里跟 Torra 结构最像的一个），以及闭源的 NNScholar 和 书生·端砚。前两个闭源产品进不了全景表，但它们在首页上展示的界面，比很多开源项目更接近“科研工作台该长什么样”的日常想象。

一个反直觉的发现：开源科研工作台里，最稀缺的不是生成能力，而是“可回去”——回到某个来源、某次运行、某一版大纲。聊天框谁都能做，能让人放心退回去的界面却很少。

全景

十九个项目，五种桌子

筛选标准很朴素：项目要真正开源（OSI 认可的许可证）、界面是给研究者日常用的、并且至少有一个可观察的完整工作流。NotebookLM、Elicit、SciSpace 这类闭源产品只作为参照，不进表；“源码可见但限制商用”的项目也不算开源。Star 数只说明社区能见度，不代表适合你的场景。

深拆

十一个界面，十一种解法

这十一个不是按 star 排的，而是按它们各自解决的一个界面问题选的：上下文、写作、停靠、执行、历史、记录、分屏、库、帧、联动，以及把危险动作变成待批卡。每个项目只抓一个最值得带走的交互，不写成产品说明书。

01

AI 原生 · MIT · 40.9k

Open Notebook：把“上下文”变成可见的第四个对象

NotebookLM 的开源复刻，但界面里最值得看的不是对话，是 Context 计数。

界面怎么排

左侧不是文件树，而是按研究动作分组的导航：COLLECT 放 Sources，PROCESS 放 Notebooks 和 Ask and Search，CREATE 放 Podcasts，MANAGE 放 Models、Transformations、Settings、Advanced；底部固定 Quick actions（⌘K）、主题、语言和退出。主区是三张等宽卡片：Sources、Notes、Chat with Notebook。

所有东西围绕一个 notebook 聚合。来源卡片上直接标“1 insights”，聊天输入框上方写着 Context 4、1.7K tokens / 6.9K chars，右侧是模型选择器。每条回答还能回指用了哪些来源和笔记。

交互签名

上下文不是设置里的开关，而是随时可见、可数、可换的对象。要加材料，点 Add Source；要从材料里提炼，点来源卡片的灯泡；要把提炼结果变成笔记，中间栏直接 Write Note。三栏之间的流向是单向可读的：来源 → 笔记 → 对话。

模型选择放在输入框旁边，而不是设置页深处。研究时人会不断在“便宜模型粗读、贵模型精读”之间切换，这个动作应该发生在提问的地方。

可迁移

对 Torra 的启示不是照抄三栏，而是承认助手只是研究的一栏。当前选中哪些来源、哪条论断，应该像 Context 4 一样以可移除 chip 的形式出现在助手输入框上方；材料、笔记、对话共享同一个作用域。

02

AI 原生 · MIT · 31.7k

STORM：大纲不是报告的附属品，是研究过程的合同

它把长文生成拆成“先调研、后写作”，并把中间物露出来。

界面怎么排

首屏只做一件事：用一个主按钮把人带进流程；真正的设计在两阶段。Pre-writing 先做检索、视角发现和模拟对话，产出 References 与 Outline；Writing 再把大纲和参考写成带引用的全文。

STORM 的关键不是“自动写”，而是“先问对问题”：它从相似主题的既有文章里发现不同视角，再模拟 Wikipedia 作者与领域专家的对话，用来源支撑追问。

交互签名

Co-STORM 把这套流程变成人机协作，并维护一张动态 mind map，把收集到的信息压成层级概念结构，作为人与系统之间的共享概念空间。README 明确说这张图是为了降低长对话的认知负担。

换句话说，界面要同时容纳两种状态：线性的对话，和非线性的概念结构。前者用于推进，后者用于回看。

可迁移

研讨的每一轮本来就类似 STORM 的模拟对话。把各模型的立场压成“视角卡”，在生成报告前先让用户确认/编辑大纲，比事后重写整篇便宜得多；mind map 可以作为 Torra 的第三个视图，而不是另一张聊天记录。

03

计算 · BSD-3 · 15.4k

JupyterLab：文档就是面板，工作区可以停靠

它把 notebook、预览、图片放进同一个可拆分的桌面。

界面怎么排

左侧活动栏只放几个图标（文件、运行中的内核、扩展），主区是标签页和可水平/垂直分屏的工作区：一个 notebook、一个 Markdown 预览和一张图片可以同时开着。顶部是菜单和 notebook 工具栏，底部状态栏显示内核与编辑模式。

它把 notebook、终端、编辑器、检查器都当成可停靠的“文档”，可以拖动、拆分、关闭；命令面板让动作可搜索，Launcher 把“新建什么”做成首屏。

交互签名

工作区是有记忆的：标签顺序、分屏比例、打开的文件在重启后还在。内核是独立对象，一个 notebook 对应一个 kernel，状态栏随时告诉你它还活着没有。

代价是隐藏状态：cell 可以乱序执行，变量还在内存里，后来者很难复现。Marimo 正是拿这一点切入的。

可迁移

Torra 目前的面板是顶层整页 iframe，报告、来源和图谱不能并排。至少应在报告页支持“报告 + 证据”分屏，并让面板的打开状态可恢复；工作台的核心不是某个页面，而是可停靠的工作区。

04

计算 · Apache-2.0 · 23.4k

Marimo：执行语义决定界面能长什么样

因为状态是确定的，才敢把依赖、stale 和 app 模式做成一等公民。

界面怎么排

截图把一个 cell 的控件摊得很清楚：左侧 + 号插入、行号、播放/停止、溢出菜单、耗时、删除、拖拽手柄和缩放；代码与输出在同一个卡片里，滑块直接绑定变量，下面的 Markdown 用 f-string 跟着变。

这些控件的底气来自执行语义：响应式 DAG，跑一个 cell 会重跑依赖；依赖没算完的 cell 被标记为 stale；notebook 存成纯 .py；同一份文件可以在编辑器和 app 视图之间切换，也能部署成 slides 或 WASM 应用。

交互签名

“运行”不再是一个按钮，而是一张依赖图上的传播。UI 控件（滑块、下拉框）是代码的一部分，不是外挂的表单；改控件等于改输入，依赖自动重算。没有隐藏状态，所以界面可以诚实地告诉你哪些结果是旧的。

代价是重算可能很贵，且生态主要在 Python。它换来的是一种可解释性：屏幕上的每个数字都能说清从哪来。

可迁移

Torra 的多轮研讨也需要“这一条结论依赖哪些轮次/来源”的可见依赖。助手工具调用、报告生成、图谱查询都可以借用 stale 的概念：上游变了，下游明确标记“待重算”，而不是悄悄沿用旧结果。

05

计算 · MIT · 1.9k

Galaxy：历史不是日志页，是工作台的右栏

每次工具运行都变成一个带状态、参数和来源的 dataset。

界面怎么排

官方训练图把三区标得很直白：左侧 Activity Bar（Upload、Tools、Workflows、Visualization、Histories、Pages），旁边是 Tools 面板（搜索 + 分类），中央是工作区，右侧是 History。

每跑一次工具，结果作为 dataset 追加到 History；dataset 有 queued/running/success/failed 状态和颜色，点开能看到参数与来源；Workflow 把多个工具连成一张图，provenance 让“这个结果怎么来的”一路回溯。

交互签名

History 不是“最近操作”，而是当前分析的完整物料清单。用户可以折叠、重命名、删除、比较 dataset；同一个工具可以用不同参数重复跑，历史里留下多条分支。

这套模型对科研特别合适：研究不是一次成功，而是几十次尝试后的可解释路径。界面把“失败的结果”也保留下来，而不是只展示最后一次成功。

可迁移

server 观测和助手工具调用应该有一条 run rail：每次运行是一帧，带状态、耗时、输入和“用同样参数再跑一次”。失败也留在历史里，报告引用时能指回具体那次运行。

06

记录 · AGPL-3.0 · 1.5k

eLabFTW：把记录做成可查询的数据库，而不是文档树

实验与资源是两个平行实体，状态和标签让整个实验室可扫描。

界面怎么排

官方 demo 的首屏不是登录表单，而是三个实验室 persona：Microbiology、Organic Synthesis、Quantum Physics，每个都能以 Admin 或 User 身份进入。它把“空产品”换成了“可探索的样例”。

进入后顶部是 Experiments、Resources、Scheduler、Team、Tools；实验列表按 Category、Status、Owner、Tag 过滤，卡片上有 Running/Success 状态；实验内部有步骤、模板、关联资源、权限和可信时间戳。

交互签名

Experiments 和 Resources 是两套并列的实体：实验记录过程，资源（抗体、质粒、细胞株、盒子）记录物料；实验可以链接资源，资源也能反查被哪些实验用过。

状态不是装饰：Running、Success、Fail 直接影响筛选和团队视图。模板把常见实验变成可复用的骨架，减少空白页焦虑；时间戳和权限把“记录”变成可审计的证据。

可迁移

研讨和报告也可以有状态（进行中/已结论/有分歧）和模板；首次启动给一个可探索的示例项目，比空白输入框更能建立心智。Torra 的“历史”现在已经是一个列表，下一步是让它可筛选、可比较、可回到某次记录。

07

协作 · AGPL-3.0 · 18.3k

Overleaf：一种文档，两种编辑姿势

代码/可视化切换，PDF 是地面真值，编译是显式动作。

界面怎么排

左侧是文件树和文档大纲；中间是 Code Editor 与 Visual Editor 两个标签；顶部是 Recompile；右侧是 PDF 预览，带页码和缩放。

同一份文档有两种编辑姿势：写 LaTeX 的人用代码，不写的人用可视化工具栏；PDF 是最终事实，编译是显式动作。历史、评论和实时协作都在同一项目作用域里。

交互签名

Visual Editor 不是另一个产品，而是同一份源码的另一种投影；切换标签不会分叉内容。编译按钮把“我改了什么”与“读者看到什么”分开，失败时错误定位回代码行。

代价是编译等待，以及 Community Edition 的能力边界：没有 sandboxed compiles，也不含 tracked changes（Server Pro 才有）。

可迁移

报告已经有阅读模式，下一步是“报告 + 证据”分屏，以及重生成时显示 diff，而不是整篇替换。模式切换比堆按钮更省认知；预览必须是地面真值，不能是另一套近似渲染。

08

知识 · AGPL-3.0 · 15.8k

Zotero：库—条目—详情，三栏的经典分工

标签是独立 facet，右侧是检查器，不是弹窗。

界面怎么排

左栏是集合树（My Library、分类、Feeds、标签），中栏是条目表（Title、Creator、Year），右栏是条目详情（元数据、摘要、附件预览）；顶部每个条目或 PDF 一个标签。

标签在左下是独立 facet，不是文件夹；保存的搜索与集合并列；右侧是检查器，不是弹窗。选中一条，详情、附件、引用键和笔记都跟着换。

交互签名

一条文献可以同时属于多个标签和多个集合，而不需要复制。顶部标签让你把几篇 PDF 同时开着，阅读上下文不会因为切换条目而丢失。右侧面板承担“当前对象是什么”的全部解释。

代价是同步和存储是付费服务，界面偏旧，PDF 阅读器与条目详情是两套上下文；插件生态在补这些缺口。

可迁移

Torra 的来源库应该能开成标签，右侧检查器显示“被哪些论断引用、来自哪一轮、原文在哪”。这比单独的文献页更有用，因为它把来源放回了正在写的东西旁边。

09

知识 · GPL-3.0 · 828

Neo4j Browser：帧是历史的最小单位

查询、结果和指南在同一个滚动栈里，结果可以换四种读法。

界面怎么排

最左是窄图标栏；第二栏 Database Information 列出 node labels（带计数）、relationship types、当前用户和 DBMS；顶部是 Cypher 编辑器；下面每一帧是一条查询加结果，结果可以在 Graph、Table、Text、Code 之间切换；:play start 是内置指南。

每次查询不跳新页面，而是往下堆一帧；帧可以折叠、关闭、全屏；右侧 Overview 列出当前图的标签和关系类型。查询、结果和指南在同一个滚动栈里。

交互签名

帧把“我做了什么”和“我看到了什么”绑在一起：回到上面某一帧，就能看到当时的查询和结果，不需要另开历史页。Graph/Table 切换是对同一结果的不同读法，而不是重新查询。

代价是 Cypher 门槛；而且这个仓库是经典版，已进入有限维护，当前官方 Browser 由闭源构建产出。

可迁移

助手每次工具调用输出一帧（输入、结果、解释），可折叠；图谱结果提供 Graph/Table 切换。对 TKGR 来说，时间戳、置信度、路径都可以是同一帧的不同视图，而不是三个页面。

10

知识 · LGPL-2.1 · 736

Cytoscape：选择要会传播，数据表要停靠在画布下

图、表、样式、过滤共享同一份选择，这是图工作台的核心。

界面怎么排

最左是任务模式竖条：Network、Style、Filter、Annotation、Legend、App Store、Layout Tools；中间是网络画布；底部停靠 Node Table、Edge Table、Network Table、Enrichment Table；最下方还有命令行。

在画布上选中节点，表格对应行高亮；在 Style 里把某一列映射到节点颜色或大小；Filter 控制显示子集；App Store 装分析插件。图、表、样式、过滤共享同一份选择。

交互签名

左侧竖条切换的是“当前任务”，不是“功能页”：同一块画布，在 Style 模式下调视觉映射，在 Filter 模式下筛子集，在 Annotation 模式下加注释。数据表不是另一个页面，而是画布的底部检查器。

代价是七个模式 + 多张表 + 命令行，对 casual user 过重；桌面安装也限制了协作。

可迁移

TKGR 的实体/关系、表格行、报告里的论断应该共用一套 selection id；右侧检查器永远显示当前选中对象。图谱面板只需要三个模式（浏览/分析/呈现），但 selection bus 和属性映射不能省。

11

AI 原生 · MIT · 109 · 上海人工智能实验室

InternAgentS：把“危险动作”变成聊天里的一张待批卡

它是这批项目里跟 Torra 最像的一个：同样是多模型、多工具、多会话的桌面工作台。

界面怎么排

左栏是项目（可切换本地项目）、新建、能力配置、设置，以及按“需要处理 / 今天”分组的会话列表；中栏是对话与输入框，输入框支持 @ 文件、# 会话、/ 技能、⌘K 搜索；右栏是项目文件面板，可切网格/列表、搜索、预览 PDF、Office、图片、分子结构与科学数据输出。

技能是一等公民：设置里有“技能管理”和“科学技能库”两个标签页，内置技能（Docx、PPT、Excel、PDF、专利申请等）各带开关，也能添加本地技能或从 GitHub 导入；模型侧可接 DeepSeek、通义千问、GLM 或自建服务。

交互签名

最有价值的一张界面是 SSH 远程计算的审批卡：卡片标着 APPROVAL REQUIRED，展开能看到命令、输出 glob、超时与等待时间、工具名与完整参数 JSON，底部是 Reject 与 Run job 两个按钮。左栏同时给待处理会话打上“需处理”“可能卡住”的徽标。

配套的授权模式是一张三选一的卡片：自动授权（推荐）、写入需审批、全部需审批，按项目风险切换。也就是说，权限不是一个开关，而是一层用户能理解、能调整的界面。

可迁移

Torra 已经在插件层做了 storage / tools / secrets / ai / net 的权限声明，缺的是把“这次调用要不要人点头”放到聊天现场：危险动作先渲染成一张待批卡，参数可展开可核对，批准与拒绝都留痕；再给研讨加一档按项目切换的授权模式，用“自动 / 写入需审批 / 全部需审批”这种用户能懂的说法，而不是暴露内部权限名。

补充

另外三个入口，补上项目 hub 与角色化助手

还有三个项目不在深拆里，但它们各自贡献了一个 Torra 可能用得上的入口设计。

AI 原生 · AGPL-3.0 · 37.9k

Khoj：助手是可切换的角色，不是固定人格

首屏不是聊天记录，而是一句问候、四个 agent 选项（Khoj、Technical Lead、Therapist、Teacher）、一个支持 “/” 命令的输入框，以及三张示例卡。它把“助手”做成可切换的角色，同时保留一个默认入口。

对 Torra 的启发：多模型研讨本身就是多角色，不必把“主持人/批评者/总结者”藏进提示词，可以让它们在界面上成为可选的视角。

协作 · Apache-2.0 · 732

OSF：项目 hub 的页签与“冻结版本”

OSF 的项目页把概览、Wiki、文件、分析、注册、贡献者收进同一组页签；components 允许把大项目拆成子项目；registration 把某一时刻的项目冻结成可引用、带 DOI 的版本。

这套信息架构对“研究报告”很有参考价值：报告不是一次生成就结束，而是可以有版本、有冻结、有引用。Torra 的“重生成”如果每次都覆盖，就丢掉了 OSF 最值钱的东西。

计算 · Apache-2.0 · 275

Renku：把会话、数据、工作流放进同一个项目

Renku 把 Jupyter 会话、数据集、工作流和环境放在一个项目下，强调“别人能重跑”。它不是最漂亮的界面，但把可复现性做成了导航结构，而不是文档里的一段说明。

对 Torra 的启发：如果未来要接计算插件，项目页应该同时显示“环境、数据、运行、结果”，不要让用户去四个地方拼上下文。

闭源参照

两个进不了表的中文工作台

下面两个产品闭源，内部实现无法核验，所以按前面的标准不进全景表，只作为参照放在这里；判断全部来自它们官网首页与公开界面的截图。它们同时也是 2026 年“科研工作台”这个词被说成同一套语言的原因：模块化入口、学科能力开关、每一步可追溯。

闭源 · 中文 · 桌面端下载

NNScholar：把七个模块排成一条编号页签

官网上排成一条编号页签：01 文献发现、02 PDF 阅读、03 研究资料库、04 Agent 案例、05 学术写作、06 AI 浏览器、07 插件与技能；主界面是三栏——左侧会话工作区，中间检索结果，右侧“可以做什么”的四张能力卡片。

两处细节值得抄：空状态不是空白，而是四个具体动作（发表研报、规划与设计、分析数据、可用报表）；每条检索结果自带 PMID/DOI、“保存到文献库”和“展开详情”，从发现到归档不断线。

闭源 · 上海人工智能实验室 · Windows 客户端

书生·端砚：左栏按研究阶段分，输入框旁边放深度档

定位是“端到端全链路 AI 科研工作台”，主张把每一次执行沉淀为可追溯、可复现的科研资产。首屏左栏按动作分组（新建对话 / 论文工具 / 课题空间 / 科研应用 ｜ 科学工具 / 科学数据 / 科学计算 / 科研模型），中栏是空态提问框。

提问框上有“快速 / 深度”两档和 Auto 模型选择，下方是学科能力 chip（高空大气环境、费型本体查询、光子能量计算）。把能力做成可点的 chip 而不是长列表菜单，等于把“选工具”压缩成一次点击。

这两个参照和前面的开源项目指向同一件事：主界面应该是“会话 + 对象 + 能力目录”三件事。能力要出现在眼前、能被点，而不是藏进设置页深处；空状态要给出下一步的具体动作；生成出来的东西要能一键归档回同一个地方。Torra 现在的助手抽屉已经有“会话”，报告工作区有“对象”，缺的是把“能力目录”摆到用户手边——比如把插件动作、模板、模型角色做成输入框上方的可点 chip。

模式

十个能直接搬进 Torra 的交互

把十一个界面横向比较，会反复看到同样的十件事。它们不是视觉风格，而是信息架构和交互约定；换一套皮肤也成立。

Pattern 01三区：材料、对象、对话

Open Notebook 把 Sources、Notes、Chat 并排；Galaxy 把 Tools、工作区、History 并排；Zotero 把库、条目、详情并排。三者的中间都是“正在被做出来的东西”，两侧分别是输入和检查。三栏不是审美选择，而是把研究循环的因果链固定在屏幕上。

落到 Torra：研究面板沿用这个骨架——来源列表、当前产物、助手/检查器；不要让插件页变成只有聊天或只有表单。

Pattern 02帧：结果要能回去

Neo4j 的每条查询、Galaxy 的每个 dataset、Jupyter 的每个输出，都是“输入 + 输出 + 参数 + 状态”的帧。帧可以折叠、比较、重跑，所以研究过程不是一条不可逆的聊天记录。

落到 Torra：助手工具调用、server 观测、报告重生成，都应该生成新帧而不是覆盖；帧里保留模型、轮次、参数和时间。

Pattern 03联动：选择要会传播

Cytoscape 的画布、表格、样式面板共享同一份选择；点一个节点，表里对应行亮起，样式和过滤跟着变。图工作台的核心不是画得好看，而是“同一个对象在不同视图里保持同一身份”。

落到 Torra：TKGR 的实体/关系、表格行、报告里的论断应该共用一套 selection id；右侧检查器永远显示当前选中对象。

Pattern 04模式：一种对象，几种读法

Marimo 有编辑/app 两种视图，Overleaf 有代码/可视化两种编辑器，Gephi 有 Overview/Data/Preview 三个工作模式。模式切换把复杂能力收进“当前任务”，而不是把所有按钮摊在一条工具栏上。

落到 Torra：插件面板应该声明自己的模式（浏览/分析/呈现）；报告已经用“阅读模式”做了正确示范，把同一套模式语言扩展到图谱和来源。

Pattern 05大纲：先立合同，再写正文

STORM 把 References 和 Outline 作为 Pre-writing 的产物，Writing 只负责把合同执行成带引用的全文。它把“准备怎么写”从模型的黑箱里拿出来，变成可检查的中间物。

落到 Torra：研讨的多轮对话天然适合产出“视角卡 + 大纲”；在生成报告前给一次确认/编辑，比事后重写便宜。

Pattern 06出处：放在手指边上

Open Notebook 的回答标注用了哪些来源/笔记；Zotero 的右侧检查器始终显示条目详情；OSF 的 registration 把某一时刻冻结成可引用版本。可信不是因为“说了来源”，而是因为来源就在点击距离内。

落到 Torra：报告里的引用应该打开右侧证据抽屉：原文片段、模型原话、轮次，以及“这条查不到原文”的状态。Torra 已经有“报告不编造来源”的原则，下一步是把它变成可点的路径。

Pattern 07空态：第一屏就是启动器

JupyterLab 的 Launcher 把“新建 notebook/终端/文件”做成首屏；eLabFTW 用三个实验室 persona 替代空登录；Open Notebook 用一个 New 按钮和三栏空态教你怎么开始。空状态不是“暂无数据”，而是产品的第一堂课。

落到 Torra：首次启动给一个可探索的示例研讨/报告，加上“文献综述 / 实验记录 / rebuttal”模板，比空白输入框更能建立心智。

Pattern 08命令：第二套导航

JupyterLab 的命令面板、Open Notebook 的 Quick actions（⌘K）、Khoj 输入框里的 “/” 命令，都是把深层动作从菜单里解放出来。对熟手是加速器，对新手是可发现的功能目录。

落到 Torra：一个全局 ⌘K，统一跳转页面、切换模型、打开插件动作、搜索历史；不要每个插件各造一套快捷键。

Pattern 09授权：危险动作先变成一张卡

InternAgentS 把一次远程计算渲染成聊天里的审批卡：标题写着 APPROVAL REQUIRED，展开能看到命令、输出路径、超时和完整参数，底部两个按钮——Reject 与 Run job。设置页再给一档三选一的授权模式（自动 / 写入需审批 / 全部需审批），按项目风险切换。

落到 Torra：插件工具调用、写入工作区、账号登录这类动作应该先停下来变成待批卡，参数可展开核对，批准与拒绝都留痕；权限用“自动 / 写入需审批 / 全部需审批”这种说法，不要把 storage、secrets 这类内部名字直接抛给用户。

Pattern 10侧栏：会话列表要能当收件箱

InternAgentS 的左栏把会话分成“需要处理”和“今天”，待处理的会话带“需处理”“可能卡住”两个徽标和时间戳；NNScholar 与端砚的侧栏则按研究阶段（论文工具、课题空间、科研应用 / 科学工具、科学数据、科学计算）分组。列表不是历史归档，而是当前待办。

落到 Torra：研讨会失败、会超时、模型掉线、插件任务未回，这些都该在模型栏或会话栏里被标出来，而不是静默失败；侧栏按“需要处理 / 今天 / 更早”分组，比一条时间倒序的列表有用得多。

落到 Torra

不是再加一个页面，而是把四条线接上

Torra 的骨架已经和这些工作台同构：顶部图标导航（研讨、聊天、翻译、历史、设置、插件），左侧模型栏，右侧检查器，报告工作区（阅读模式、目录、筛选、搜索、导出），助手抽屉，以及 scholar/server 两个 iframe 插件页。缺的不是“再来一个页面”，而是四样连接。

顶栏：研讨 · 聊天 · 翻译 · 历史 · 设置 · 插件面板
模型栏
报告工作区 / 插件页
阅读模式 · 目录 · 搜索 · 导出

助手抽屉（可全屏）

先把“出处”接上

报告已经有“这一条没有记录原话。报告不编造来源。”的原则，说明价值观已经在了；下一步是把它变成可点的路径。点击一条引用或一个论断，右侧滑出证据抽屉：原文片段、模型原话、所在轮次、置信/分歧状态。参照 Zotero 的 item pane 和 Neo4j 的 frame，不要跳页，也不要用 modal 打断阅读。

把“重跑”做成帧

每次报告重生成、助手工具调用、server 观测，都生成一帧而不是覆盖：参数、模型、轮次、时间、状态、diff。参照 Neo4j 的查询帧、Galaxy 的 history、OSF 的 registration。用户需要能说“用第三版的来源、第二版的模型再跑一次”，而不是只剩最后一版。

给插件一个共同的面板壳

scholar 和 server 都是 iframe，各自有导航，用户很难知道“哪个在跑、哪个有未保存状态、哪个有未读结果”。统一的面板壳至少提供：标题、状态、来源计数、刷新、历史、模式切换。参照 Galaxy 的三区边界与 JupyterLab 的面板生命周期；插件内容仍然沙箱化，壳只负责宿主级信息。

把越权的动作变成待批卡

Torra 的插件权限已经写在 manifest 里，但用户看不见它。参照 InternAgentS 的审批卡：插件要写工作区、调用网络、动 secrets、替用户登录时，先在对话里生成一张卡，写清“做什么、在哪个项目、参数是什么”，用户点批准或拒绝，批准与拒绝都进历史。再配一档按项目切换的授权模式——自动、写入需审批、全部需审批——比事后在日志里追究更便宜。

低成本、可以马上做的还有四件：一个全局 ⌘K（跳转、切模型、开插件动作、搜历史）；一套首次启动的模板与示例研讨；把插件动作、模型角色、模板做成输入框上方的可点 chip（参照端砚的学科能力与 NNScholar 的“可以做什么”卡）；窗口窄于 1200px 时把右侧检查器收成抽屉，而不是继续压三栏。最后一条是从 Galaxy 和 Zotero 的截图里直接能看出来的教训：三栏在宽屏是效率，在窄屏是灾难。

也有四件事不值得照抄：Cytoscape 的七模式竖条、Galaxy 的双侧栏、Neo4j 的 Cypher 优先、Overleaf 的编译等待。它们不是设计得差，而是服务于高频专业用户；Torra 的用户跨度更大，渐进披露比“把所有能力摊开”更合适。Torra 现在的暖纸色 + 黛青已经更接近 Zotero/Overleaf 这类阅读型工作台，保留这个方向，不要把图谱页做成另一套深色工具。

如果只做四件事：证据抽屉、帧与 diff、统一面板壳、待批卡。前两个决定研究是否可信，第三个决定插件是否能长成生态，第四个决定插件生态会不会变成事故。

附录

核验与来源

这份调研在 2026-10-29 至 10-30 用 GitHub API 取候选项目的 stars、许可证与最近推送时间，并在删表前把在表项目全部重取了一遍，最终 19 个入表。界面判断来自官方 README 截图、官方文档、官方 demo 或在线实例；桌面软件没有逐一下载安装，因此关于“点击后发生什么”的描述只写到截图和文档能支持的程度。

怎么做的

先按“研究发生在哪一层”建立候选池，再排除闭源、source-available、停更和无界面的项目。深拆对象的选择标准是“每个项目至少解决一个不同的界面问题”，而不是热度。Open Notebook 与 Khoj 的截图取自 README 动图帧；Marimo 同样取自动图帧；Galaxy 使用官方培训材料的标注图；eLabFTW 使用官方 demo 的 headless 截图；其余桌面软件使用官方截图。OSF 的根域在 headless 环境下返回 403，因此没有用 OSF 的界面截图，关于项目页结构的判断来自官方文档与 PMC 上的 OSF 论文；STORM 的在线实例有 ToS 门槛，截图只到首屏，工作流描述来自 README 与论文。

InternAgentS 的界面证据全部来自仓库内的官方素材：README 的工作区截图，以及 docs/assets/user-manual 与 ui/public/showcase 下的工作台、文件预览、审批卡与技能库截图；仓库结构（三栏 UI 在 ui/，LangGraph/DeepAgents 运行时装在 Python 侧，技能在 skills/，连接器在 mcp/）通过 GitHub API 的文件树核对。NNScholar 与书生·端砚是闭源产品，只截取了官网首页展示的界面，判断限于官网文案与公开截图。

需要留意的边界

“开源”不等于“可商用”。AGPL 与 GPL 都有 copyleft 义务；LGPL 的边界更窄；Apache-2.0 与 MIT 最宽松。表里的许可证是仓库声明，具体使用还要看依赖、插件和品牌资产。Zotero 是 AGPL-3.0；Overleaf Community Edition 是 AGPL-3.0，但 tracked changes、sandboxed compiles、SSO 等能力在商业版；Galaxy 从 2026-02-25 起改为 MIT，之前的版本是另一套许可；Neo4j Browser 的经典仓库是 GPL-3.0，但当前官方 Browser 由闭源构建产出，仓库本身也进入有限维护。

停更与归档要单独看。OSF 的 ember 前端仓库在 2026-04 归档，但 osf.io 主仓库仍在活跃；STORM 的主仓库最后一次推送停在 2025-09，它自己也说明这是研究预览阶段、不能直接产出可发表的文章。Stars 是社区能见度，不是界面质量或维护承诺。

候选是怎么被筛掉的。有三个项目按前面的标准只作参照、不进表（NotebookLM、Elicit、SciSpace 都是闭源），另外五个虽然开源，却在“界面是不是给研究者日常用的”这一条上站不住，于是被删掉了。RStudio 最容易被 star 数掩盖：AGPL 覆盖的只是桌面 IDE，真正叫 Workbench 的工作台形态是闭源商业产品，而 R IDE 的形态本来也不是 Torra 要做的东西；Whole Tale 最后一次推送停在 2021 年 4 月，早已停更；Apache Zeppelin 的段落式 notebook 是 JupyterLab 面对同一个问题的第二个答案，Torra 并不做 notebook；RSpace 与 eLabFTW 重复解决“实验记录”，Fidus Writer 与 Overleaf CE 重复解决“在线协作 LaTeX”，这两个位置各留一个代表就够。删掉之后，表里剩下的每个项目在正文里都被真正拆过或引用过，没有只挂个名字的。

截图是某一刻的界面。项目会改版；eLabFTW 的 demo 数据每 24 小时重置；STORM 是研究预览，明确说自己不能产出可直接发表的文章；Neo4j 的新旧 Browser 是两套产品。把这些截图当作“设计证据”，不要当作功能承诺。

新加的三个参照各有各的折扣。InternAgentS 是 MIT，但仓库名是 qzzqzzb/OpenClaudeScience，官网 internagents.github.io 的 Star 按钮指向它，而 InternAgents/InternAgentS 这个同名仓库是 2026-07 才建的空壳；仓库最后一次推送是 2026-07-13，109 stars 说明它刚起步不久，别把它当成熟产品。NNScholar 与书生·端砚闭源，页面呈现的是营销口径：端砚的“端到端全链路”、NNScholar 的“完成一切”，都只是首页文案，报告里没有对它们的内部实现下任何判断。Anthropic 的 Claude Science 是闭源商业产品（2026-06-30 发布 beta），InternAgentS 自称是把那套体验带给开源社区，两者的具体差异无从核验，因此报告不把 Claude Science 放进对照表。

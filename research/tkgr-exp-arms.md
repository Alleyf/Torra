## 7. 归因与经验教训

**L20（组合臂必须先对最佳单臂归因）**
EA 对 base 的配对增益 +.0209/+.0147，三 seed 全过门槛；但对 EM 只有 +.0057/−.0006（seed42 +.0148/+.0016，seed43 +.0029/−.0009，seed44 −.0006/−.0026）。强底座会把组件收益吃掉，而且两条改动共享同一瓶颈（投影尺度）时会出现负交互。以后组合臂一律先报 `组合−最佳单臂`，再报 `组合−base`；EA 因此判弃，不再排 `EU = EM + AU` 这类同层组合。

**L21（All MRR 会掩盖名次再分配）**
TT 的 Emerging H@10 +.0350、H@3 +.0243，但 Unknown H@1 −.0086；All 只涨 +.0082（差 .0008 未过门槛）。它把已知实体的头部命中挪到尾部，把名次让给新兴实体。结论：不能因为 Emerging 单项大涨就收；必须同时看 Unknown 的 H@1。

**L22（EM 是唯一双集都涨的机制臂）**
EM 同时提升 Emerging +.0154 与 Unknown +.0087，Unknown H@3 +.0168 / H@10 +.0161。说明“训练期见过空链状态”让模型对两种实体状态都更可分，不是只对新兴实体有效。后续组合应以 EM 为底座。

**L23（残差/归一化的分解）**
AR 单独 +.0073/+.0006；AU 在 AR 上再加 LN 到 +.0194/+.0113；AN 单独 +.0153/+.0110。LN 是主贡献，残差是稳定器。EA 选 AN 而非 AU 本身是次优组合；但按 L26，`EU = EM + AU` 这类同瓶颈叠加也不再排——组合只做跨项/跨层。

**L24（引用审计）**
引用核验要核“编号对应的标题与主张是否一致”，不能只核编号存在。本轮抓到 `arXiv:1907.06610` 被误当成冷启动元学习先例（实际是 QCD 物理论文，PRD 100, 074013），已改为 MeLU（arXiv:1908.00413）与 MetaKG（arXiv:2202.03851）。

**L25（“Best test”不是 FINAL）**
日志会先打 `Best test: Emg ...`，最后才打 `FINAL test MRR:`；以 `Best test` 判定完工会把早停后的收尾误报成结束。判定一律用 `FINAL test MRR:` 或 `run.json status=="finished"`，两条都要求。

**L26（同层组合的负交互）**
EA 的 ΔAll 随 seed 单调下降（+.0148 → +.0029 → −.0006），不是随机波动，而是两条改动共享同一瓶颈（768 维文本投影后的打分尺度）导致的饱和。组合臂的准入从此改为：作用在不同的项 + 写出交互机制 + 预注册可证伪的交互预测；同瓶颈同层叠加一律不排。

**L27（本轮引用逐条核对，一条会址被改正）**
按“编号 → 标题 → 主张”逐条核对（arXiv abs 页原文）：`2604.10164` = *Inductive Reasoning for Temporal Knowledge Graphs with Emerging Entities*（TransFIR，2026-04-11）；`2304.00613` = *Improving Few-Shot Inductive Learning on TKG using Confidence-Augmented RL*（**FITCARL，ECML/PKDD 2023**，不是 ACL 2023 —— 已改正，M2 协议因内容变更从 v1 升到 v2 并重新登记）；`2211.08169` = *Few-Shot Inductive Learning on TKG using Concept-Aware Information*（AKBC 2022）；`2205.10621` = *Learning Meta Representations of One-shot Relations for TKG Link Prediction*（IJCNN 2023）；`2006.06648` = *GEN*（NeurIPS 2020）；`1908.00413` = *MeLU*（KDD 2019）；`2202.03851` = *MetaKG*（TKDE 2022）；`2103.10379` = *ChronoR*（AAAI 2021）；`1711.03438` = *Open-World KGC / ConMask*（AAAI 2018）。其余标准引用（MAML 1703.03400、Reptile 1803.02999、ProtoNet 1703.05175、GraphSAGE 1706.02216、GraIL 1911.06962、SimCLR 2002.05709、CLIP 2103.00020、SupCon 2004.11362、Perceiver 2103.03206、Set Transformer 1810.00825、TCN 1803.01271、TGN 2006.10637、TGAT 2002.07962、Time2Vec 1907.05321、KEPLER 1911.06136、FiLM 1709.07871、HyperNetworks 1609.09106、LayerNorm 1607.06450、scheduled sampling 1506.03099、MoE 1701.06538、logQ 1906.00091、conformal 2107.07511）逐条对标题无异议。

**L28（L26 的例外必须是「符号分裂」并预注册，不是事后挑数据）— 已证实**
AU−EM 的配对结果是 **All +.0042 / Emg −.0041**：两个指标符号相反，说明 AU 与 EM 优化的是不同的项，而不是 EA 那种「同一投影尺度上的两条改动」。因此 AU+EM 是 L26 的可证伪检验，而不是对 L26 的推翻。准入条件写成可证伪预测（02:12 预注册，先于任何 AUEM 结果）：`AUEM−EM` 的 ΔAll ≥ 0 且 ΔEmg ≥ −.005；若 ΔAll < 0，则「EM 底座 + 同层组件」共享瓶颈的解释成立，AUEM 与 EA 同判，不再尝试任何同层组合。
**结果（06:52 UTC 三 seed 齐）**：`AUEM−EM` = **+0.0091 / −0.0009**（3/3 ΔAll 正：+.0142/+.0088/+.0044），预测成立 → L26 的例外条件被验证，AUEM 保留。反向证据同样成立：EA 的 `EA−AU` 只有 +.0015/+.0035/−.0025，说明「EM+AN」不是有效组合，符号分裂判据确实能区分前者与后者。

**L32（组合的收益来自「作用在不同项」，不是来自叠得更多）**
两条改动只有在**作用项不同**时才能相加：EM 改的是训练期分布（空链状态对齐），AU 改的是投影后的打分尺度（残差 + LN）；`AUEM−AU` = **+0.0049/+0.0032/+0.0005**（3/3 ΔAll 正），说明组合确实加在最佳单臂之上。反例是 EA：AN 与 EM 都作用在「记忆读入 → 投影」这条链上，`EA−AU` 的 ΔAll 仅 +.0015。教训：以后判断组合先问「两条改动是否更新同一个量」，而不是「两条臂是否都有效」；有效但同项的臂相加会饱和（L26），不同项的臂相加才会超过最佳单臂（L28/L32）。

**L29（被弃臂的单项信号要留作分析素材，不要救整臂）**
TT 被整体判弃（ΔAll +.0082 未过门槛、Unknown H@1 −.0086），但 Emerging H@10 **+ .0350（全表最高）**、H@3 +.0243 是独立的长尾召回信号：新颖度路由在新实体的尾部召回上有独特作用，代价是把已知实体头部命中挪到尾部（L21）。写论文时作为「路由的收益与代价」的机制分析素材保留，不再为它加 seed 或调参。

**L30（换「优化项」的机制/架构臂在 EM 底座上被系统性覆盖）**
M3（训练期对比对齐）与 A2（文本 kNN 子图）都属「换一个优化项/推理结构」，对 base 有增益（M3 +.0134/+.0143 三 seed 全过门槛；A2 +.0116/+.0099，但 seed42 ΔAll +.0062 未过门槛），但 `臂−EM` 全为负（M3 −.0018/−.0011、A2 −.0036/−.0055，A2 的 ΔAll 3/3 为负）。M2（元学习，换训练范式）更进一步：对 base 直接掉点（**−.0157/−.0080**，3/3 ΔAll 负），`M2−EM` −.0308/−.0234。把 L22/L26 串起来：EM 已经把「零历史分布差」这个主瓶颈对齐掉，之后同层再换优化项、甚至换训练范式的边际收益都为负。结论：机制/架构级新 idea 要么换**表示来源**（B1 文本优先骨干）、要么换**记忆粒度**（B2 事件级记忆）、要么换**评测单元**（P1/P2），不再在 EM 底座上堆同层臂。唯一例外是 L28 的「作用在不同项」组合（AUEM），它已过线。

**L31（队列空闲判据不能用利用率，必须看进程）**
03:21 UTC 事故：`gpu_free` 用 `util<15% 且 used<3000MiB`，A2-42 进入验证阶段时 GPU util 掉到 0、显存占用只有 1.8GB，被判成「空闲」，M2-42 同卡并行跑了 14 分钟（gpu0 used 3.7GB）。修复：`queue_p1_ideas_next2.sh` 改为 `used<500MiB` **且** `nvidia-smi --query-compute-apps=pid` 进程数 = 0，并退役旧监听。教训：只要卡上还有训练进程就永远不算空，util 是 5 秒瞬时值，验证/数据加载阶段天然会归零。所有正式数字必须单卡独占；本轮只有 A2-42 的墙钟被拖慢，若其 FINAL 落在异常区间，重跑一次再进配对表。

## 9. 多层级新 idea 与文献支撑

原则：每条 idea 都要有可查文献、能落到本仓库与 fcs 闸管流程、有可证伪阈值、不改评测口径（L5）。当前主指标 All / Emerging，门槛为同机 seed 配对 ΔAll ≥ +.009 且 3/3 同号、ΔEmg ≥ −.005。

### 9.1 问题级
- **P1 · 首现事件预测**：把评测单元从“test 子集的四元组”改成“实体首次出现的连续事件流”。依据：TimeTraveler（ACL 2021.emnlp-main.655）的 Inductive Mean；TransFIR（arXiv:2604.10164）把零交互新实体作为一等对象。属于评测层改动，按 L5 只写设计、不跑。
- **P2 · 开放世界不确定性**：输出预测集合/覆盖率而非单点排序。依据：Conformal prediction（arXiv:2107.07511）。同样属评测层，暂不跑。

### 9.2 骨干级
- **B1 · 文本优先骨干**：弱化 VQ 身份码本，BERT 文本向量作主表示。依据：KEPLER（arXiv:1911.06136）、TransFIR 的 Collapse Ratio 分析。风险：VQ 是现有迁移机制，去掉可能掉点。暂不跑。
  **代码事实（2026-11-04 核对 `model_enhanced.py`）**：`--word_embedding_path` 打开时 `self.entity_embedding` 是普通 tensor（L124-126），**不参与优化**；实体表示本来就是「冻结 BERT 文本 + 学到的 `project`/`proj_norm`」。而且 VQ 的 `quant` 在 forward 里算出后**从未进入打分**（grep `quant` 只有 L323、L336-338），只有 `pseudo_onto_idx` 被用作 drift 的聚类索引。所以这条 idea 的原始表述（「VQ 是身份路径」）在这个代码里不成立；B1 的实质只剩「去掉 VQ 的辅助损失与聚类漂移」，属于组件级清理，不是骨干级改进。
- **B2 · 事件级记忆骨干（TGN/TGAT 式）**：per-entity EMA 换成事件级记忆 + 连续时间编码。依据：TGN（arXiv:2006.10637）、TGAT（arXiv:2002.07962）。实现重；MS 已被否，B2 是骨干级下一候选。
- **B3 · 多尺度链骨干（MS）**：已实现并三 seed 验证，**ΔAll +.0016，未过门槛，弃**。依据：Set Transformer（arXiv:1810.00825）、TCN（arXiv:1803.01271）、Time2Vec（arXiv:1907.05321）。

### 9.3 架构级
- **A1 · 双塔 + 新颖度路由（TT）**：已三 seed 验证，**ΔAll +.0082 未过门槛，且 TT−EM 双负，弃**。依据：MoE（arXiv:1701.06538）、logQ 纠偏（arXiv:1906.00091）。
- **A2 · GraIL 式子图推理**：文本 kNN 建子图，在子图上跑关系路径推理。依据：GraIL（arXiv:1911.06962）+ GraphSAGE（arXiv:1706.02216）+ TransFIR 的语义相似实体模式迁移。**已三 seed 验证，判弃**：三 seed 均值 All 0.3933 / Emg 0.1945 / Unk 0.2254；seed42 ΔAll +.0062 未过门槛，`A2−EM` = −.0036/−.0055（3/3 ΔAll 负）。
- **A3 · Perceiver 式历史压缩**：变长历史压成固定 latent。依据：Perceiver（arXiv:2103.03206）。对零历史无直接帮助，仅设计。

### 9.4 机制级
- **M1 · CS 冷启动簇原型**：已三 seed 验证，**ΔAll +.0075 未过门槛，且 CS−EM 三 seed 全负，弃**。依据：ProtoNet（arXiv:1703.05175）、GraphSAGE（arXiv:1706.02216）。
- **M2 · 情景式元学习**：把「实体首现后的前 k 个事件」当 task，内循环只用 `history < t` 做几步适配；零历史行回落到元初始化。依据：MAML（arXiv:1703.03400）、MeLU（arXiv:1908.00413）、MetaKG（arXiv:2202.03851）、FITCARL（arXiv:2304.00613）、FILT（arXiv:2211.08169）、GEN（arXiv:2006.06648）、MOST（arXiv:2205.10621）。**已三 seed 验证，判弃**：All 0.3661 / Emg 0.1766 / Unk 0.2137，对 base −.0157/−.0080/−.0100（3/3 ΔAll 负），`M2−EM` −.0308/−.0234。
- **M3 · 文本-链 InfoNCE 对齐**：三 seed 收口。All .3947/.3961/.3946、Emg .1976/.2005/.1985；对 base 全过门槛（+.0126/+.0101/+.0175，+.0071/+.0217/+.0141），但 `M3−EM` = **−.0018/−.0011**（seed42 +.0045/−.0052、43 −.0045/+.0009、44 −.0053/+.0010）→ **弃**。依据：SimCLR（arXiv:2002.05709）、CLIP（arXiv:2103.00020）、SupCon（arXiv:2004.11362）。

### 14.15 LMW 预注册：写侧算子从来没训练过（2026-11-05 12:10 UTC，先于任何结果）

**发现（不是推断，是实测）**：`EMAAdapter.update_entities` 原来带 `@torch.no_grad()`，且 `forward` 里 `inter = self.interaction_encoder(...)` 的结果在传入前就 `.detach()`。CPU 单测（E3 树，16 维玩具配置）打印 `interaction_encoder` 四个参数与 `raw_decay` 的 `.grad`，全部是 `None`；抓 E3 / AUEM / GLB 三棵树的 checkpoint，`raw_decay` 都精确等于初值 `2.0`（即 `d = sigmoid(2) = 0.8808`）。
**含义**：所谓「可学习 EMA」实际是「**固定的随机投影 + 固定衰减**」，写进去的记忆内容是一个初始化后再不变化的 MLP 对 `(chain, relation)` 的输出，只有读侧 `gate_net` 在学。这解释了为什么 CS/CCD/ESM 这些**改「写什么」**的臂一直弱：写算子本身没有可塑性，改输入等于换个固定投影的输入。

**臂**：E3 底座 + `--learned_write on`。v1（已证伪）把无界残差直接加到状态上：`new = d·m + (1−d)·avg + MLP([m, avg])`，末层零初始化。实测 39 步内 `mem_absmax` 0.13 → 8e2（每步约 ×2.2，残差喂回自己的输入），第 44 步 `LogSoftmaxBackward0` 返回 NaN（Adam 每步每权重固定走 ~lr，残差一旦非零就正反馈）。**v2（现行）把扰动改成写内容上的有界项**：
`content = avg + tanh(MLP([m_old, avg])) · RMS(avg)`，`new = d·m + (1−d)·content`。
EMA 仍是收缩映射，单元素扰动 ≤ 内容自身 RMS。MLP 末层零初始化，初始化时 `max|diff| = 0.0`（train 与 eval 两条路径都验过）。`entity_memory` 只存 `new.detach()`；同 batch 里刚写过的查询实体在 `get_adaptive_embedding` 用带图的值（`_shadow`，每次 `forward` 开头清空），写算子由该 batch 的 loss 训练；候选侧读的一律是 detach 后的 buffer。**评测期也走同一个写算子**（`torch.set_grad_enabled(False)` 只掐图，不换公式），否则读门在训练见过的记忆分布与测试时不一致。
**为什么不是 ReZero 的 `w·MLP`（w=0）**：单测验过，`w=0` 时**连 MLP 自己的梯度都是 0**（链式法则里 w 是乘子），只有 w 在动，起步慢一层；末层零初始化没有这个问题——末层第一步就有非零梯度（末层 `0.31/0.56`，前两层随后跟进）。

**代码**：`01_code/tkgr/adatkg_p1_lmw`（E3 树副本 + `--learned_write {off,on}`，只改 `modules_enhanced.py` 的 EMAAdapter 与 `model_enhanced.py`/`main_enhanced.py` 的接线）；变体 `lmw_write`（n_keys **170** = 166 + 4 个 `write_mlp` 参数；实测 checkpoint 170 键、全有限）；协议 `icews14_p1_fcs_lmw` v1（hash=1c668ba6544dc11e，已 `register_protocol.py` 登记）。`learned_write=off` 与 E3 逐位等价。
**smoke 记录（12:11 / 12:47 / 13:05 UTC）**：
1. v1 无界：第 44 步 NaN（见上）。
2. v2 单 epoch：Train loss **6.1944 / MRR 0.1223**，对照 E3-42 epoch0 **6.2415 / 0.1232**（差异只在随机性）；Test All **0.1560**；190 步内 `mem_absmax` 稳定在 0.85、`mem_norm≈2.0`。
3. v2 两 epoch（含 epoch 间 `reset_memory` 与评测路径）：epoch1 loss **5.1304 / MRR 0.2248**，Test All **0.2788**；checkpoint 170 键全有限，`write_mlp.2.weight` absmax **0.0219**（确实在学），`raw_decay` 仍为 **2.0**（设计如此，decay 依旧冻结），`entity_memory` absmax **1.43**（有界）。

TT 的 Emerging H@10 +.0350 看似大捷，H@1 却 −.0086、Unknown H@1 −.0086。Emerging 的 H@1（0.11 量级）离 H@3（0.23 量级）差一倍，说明名次大量堆在 2–3 位；任何新臂必须单独报 Emerging H@1。

**L36（论文表与官方基线差 6%，差的是实现不是 split）**
论文表 AdaTKG 的 Emerging .2011，gpu-master 官方基线跑出来 .1891（0.94 倍）。既然官方代码只有 re_split，这 6% 只能归到代码快照/超参/评测细节；写论文时要么用同一份代码重跑，要么只写同划分相对提升。把论文数当基线，等于给自己虚报 6% 的进步空间。

**L37（「更多历史」不等于「更好的历史」）**
MS 把链池化到全局 + 最近 3 事件，ΔAll 只有 +.0016；CoH 用 LLM 读高阶历史有效，说明缺的是历史的结构（逐实体事件序列），不是窗口宽度。任何 B2 类改动必须先跑「同参数量、打乱时间戳」的对照，证明增益来自事件结构而不是参数变多。

**L38（`nn.Parameter(t).to(device)` 会静默地不训练——参数验收必须查 checkpoint 键）**
torch 2.1 实测：`nn.Parameter(...).to(device)` 返回的是普通 Tensor，赋值给模块属性后**不进 `state_dict`、不进 `optimizer`**，也不会报错。后果：解码器关系表（ConvTransE 的第二输入通道）在**所有已跑臂**里都是冻结的随机 xavier 向量；`empty/cls/filling_embedding` 同样冻结。发现方式不是读代码，而是 `n_keys=166` 与「must 键」对不上。以后任何新增参数，smoke 验收必须包含 `n_keys` 与 `must` 键检查，并显式跑一次「参数确实变了」（如打印 λ 或范数）。

**L39（`set_detect_anomaly(True)` 写在 forward 里，所有臂都在为调试付训练时间）**
`model_enhanced.py` 的 `forward` 第一行就是 `torch.autograd.set_detect_anomaly(True)`（base 树第 261 行，b5 树第 284 行）。它是全局开关，一开就常驻，backward 每步都做额外检查；PyTorch 文档明确它只用于调试。所有已跑臂同享这个开销，所以**对比公平性不受影响**，但单臂 4.5 小时的墙钟里有一部分是纯浪费。下一轮开跑前应把它删掉或挪到环境变量后面；它不改变数学，关掉后数值应当逐位一致（值得用一条 1 epoch 的对照确认）。

**L40（预注册门槛必须先做量纲核对：目标桶占比 × 单桶增益上限 ≥ 主门槛）**
B5 的目标桶 `tail_unseen` 占 2.0%，CGM 的目标桶 `==1` 占 1.7%。两臂的主门槛都是 ΔAll ≥ +.009，而这两个桶即使被完全修好（+0.07 的桶内 MRR 已经算极端乐观）也只能贡献 +0.0015。**这不是预测失败，是判据在算术上就不可能被满足**——臂还没跑就已经注定判弃。以后写预注册，先把「目标桶 n / 全集 n × 单桶可期增益」算出来贴在门槛旁边；算不够门槛，要么换目标（直接对主集合设门槛），要么承认这是诊断臂、不设主门槛。另一个推论：**Emerging 集合里 55.9% 是「头实体零历史」，40.1% 是「头实体 ≥3 次」——任何只针对零历史行的方法，最多也只能碰到 Emerging 的一半，另一半必须靠常规候选质量。**

**L43（同一份信息，注入表示优于注入分数）**
四条臂都在给候选喂「候选自己的历史」，四条都亏：CSM（−.0373）、B5（−.0114）、E5（−.0195）、E3C（−.0350，且把 CSMG 的 Emerging 从 .2249 削到 .2159）。唯一赚的 E3 做的是另一件事：把 AUEM 已为查询实体算好的记忆读**并进候选表示**（`h_cand` 侧共享读），分数路径一字没改。差别不在信息源，在**注入点**——加到 logit 上等于用一次标量投影去解释一份高维证据，还得和主打分器竞争梯度；并进表示则让打分器自己决定怎么用。E3 的增益（+.0145 All、+.0079 Emg、+.0165 Unk）是在**零新增参数**下取得的，这条对照因此没有容量混淆。

**L44（争同一信号的组合不是互补）**
E3C 是 E3 与 CSMG 的叠加，预注册假设「E3 管 All、CSMG 管 Emerging」。实测 `E3C−E3` = −.0350/+.0095，`E3C−CSMG` = +.0135/−.0090：两者都在读「这个候选有多少历史」，叠加后互相稀释，Emerging 反而低于 CSMG 单独。判据要写死「组合必须 ≥ 最佳单臂」，否则这种臂会被误读成「有用但代价大」。推论：组合前先问「这两个机制读的是不是同一个量」；是，就不要组合，选注入点更好的那条。

### 17.1 B4（关系侧文本初始化）：已实现并排队

## 18. 关系级归纳：诊断、文献与候选 idea（2026-11-04）

### 18.1 结论先行：局限为真，但现有主表测不到

- **主表测不到**：按协议 `re_split`（时间切 0.5/0.2/0.3）实际得到 train/valid/test = **44343 / 17417 / 28970**（原始三文件合计 90730）；test 中「查询关系在 train 未出现」的四元组只有 **22 条（0.076%）**。也就是说 §1 的 All 0.4060 是在**关系词表全见**的 transductive 设定下取得的，不能用来支持任何关系级归纳主张。
- **代码根因**（跑实验用的是 `model_enhanced.py`，不是 `model.py`；两者都有同一段代码）：L137-139 `self.relation_embedding = nn.Parameter(torch.Tensor(num_rel_doubled, relation_dim)).to(device)`；L280 `query_relation_embedding = embedding_dict["relation_embedding"][ground_truth[:, 1]]`（这一份来自 `emb_dict`，**是** `nn.Parameter`，进优化器）；L309 经 `self.bn_relation` 后进入 L414 `self.decoder(query_embedding, self.relation_embedding, ...)`。`knowledge_graph.py` 从 `relation2id.txt` 建 `relation2id`，未见关系没有行、没有向量。
- **更严重的一条（2026-11-04 10:20 UTC 实测）**：解码器吃的那张 `self.relation_embedding` 在 torch 2.1 里因为 `.to(device)` 退化成**普通 Tensor**——不进 `state_dict`、不进 `optimizer`。AUEM seed42 的 checkpoint `n_keys=166`，其中没有 `relation_embedding`/`empty_embedding`/`cls_embedding`/`filling_embedding`。也就是说，**解码器关系通道一直是冻结的随机 xavier 向量**，只有查询侧（`emb_dict["relation_embedding"]`）在训练。B4 换的是那张冻结表（随机→文本），B6 才是把它变成可训练。
- **不对称是最直接的缺口**：实体侧有 BERT 文本初始化（`main.py:245` 读 `ICEWS14_Bert_Entity_Embedding.npy`，`main.py:309–313` 注入模型），关系侧只有随机初始化的 ID 表。同一份自然语言关系名（`relation2id.txt` 里是 `Make_statement`、`Reject_request_for_military_aid` 这类 CAMEO 事件类型），实体拿到了文本、关系只拿到 ID。
- **数据条件**：共 230 个关系，按有效切分 train 见 **211**、valid 181、test 191；全量频次极端偏斜（最大 15578、最小 1、均值 394.5），train 内 ≥500 的仅 **20** 个。首个出现时间按全量 365 个时间戳四分位分布为 **Q1 193 / Q2 18 / Q3 11 / Q4 8**，且 Q4 的 8 个关系各只有 1 条事件 → **按时间切「关系涌现」没有评测质量**，主协议只能用 hold-out 关系切分。

### 18.3 协议 P3-R（新开一张表，不改主口径）

- **切分**：按有效 train 频次排序，hold out `rank[18:28]` 的 10 个关系（同时屏蔽其反向关系），从 train 删除这些关系的全部事件。代价：训练事件 −8.60%（3812/44343）；收益：test 中 **2240 条** unseen-relation 查询（7.73%）。切分固定，seed 42/43/44 只用于初始化方差。
- **三组指标**：`Rel-Unseen`（2240 条，主指标）/ `Rel-Seen`（其余 26730 条，回归守卫）/ `All`。
- **必须新增对照臂 `base_unk`**：ID 表 + 一个可学习 `<UNK-relation>` 槽，未见关系全部映射到该槽。没有这个臂，任何「提升」都是拿一个无法运行的模型作对比。
- **2×2 因子**：{entity seen / unseen} × {relation seen / unseen}，用于检查 EM/AUEM 的实体收益在关系未见时是否还在。这是把「实体轴」与「关系轴」拼成一张新主表的唯一方式。
- **门槛（起跑前写死）**：主表 All 回归 ≥ −.005；`Rel-Unseen` 上 `C5−base_unk` 的 ΔMRR ≥ +.03 且 3/3 同号；`Rel-Seen` Δ ≥ −.005。
- **稳健性**：第二折 `rank[28:38]`（10 个关系、991 条查询）只作方向性复核，不进门槛（样本仍偏小）。

**A5 的样本量体检（2026-11-04 17:30/17:40 UTC，实测非估算）**

1. **关系级波动分档没有样本**：按 re_split 真口径（三文件合并 90730 → 44343/17417/28970，与 §18.1 一致）统计逐时间步事件率，CV = `std/mean` 的 quartile 切点为 1.08 / 2.06 / 2.79（116 个关系历史事件 ≥20）。test 查询落在四档的条数是 **25547 / 1902 / 908 / 332**——最高波动档只有 **332 条（1.1%）**。这条判据在本数据集上没有统计功效。
2. **查询时点的尖峰分档也是退化的**：改成 `spike(r,t) = (count_r(t)+1)/(EWMA_slow_r(t−1)+1)`（半衰期 10 步，只用 t 之前的信息）后，28970 条 test 查询的 spike 分位数为 0.83 / 0.98 / 0.99 / 1.00，五分位桶大小 5788 / 5799 / 5758 / 5829 / 5796——**桶内几乎无差别**。原因是粒度：test 有 110 个时间戳、230 个关系，平均每个 `(relation, timestamp)` 只有 **约 1.1 条事件**，`+1` 平滑把比值压平了。
3. **结论**：ICEWS14 在 `(relation, timestamp)` 粒度上太稀疏，**不足以支撑「多频段时间编码」这类方法的前提**。这与本项目时间轴上一连串的零结果（Z 关系码本、CSM 的 0.98 单一衰减、Y 的 kNN 时间增强都未过门）一致——不是那些实现都写坏了，而是这张表里「关系的时间动态」本身的信号量不够。A5 因此**不进队列，不占卡**；改在 ICEWS14 之外的稠密数据集（如 ICEWS18/WIKI）上再评估。

### 18.5 排序与「为什么不是又一个组件」

1. **P3-R + `base_unk`（3 seed）→ C5（3 seed）**：6 个 run，约两波。C5 是唯一能立刻把「关系级归纳」从口号变成数字的臂，且改动小（只换关系表示的来源）。
2. C5 过线后：M5（3 seed）与 `AUEM+C5`（3 seed）。组合必须先报 `组合−最佳单臂`；按 L32 先问「两条改动是否更新同一个量」——C5 改**关系表示来源**，AU 改**打分尺度**，理论上作用在不同项，是 AUEM 之后少数仍可辩护的组合。
3. A4 放在 C5 之后：它是 C5 的结构补丁，没有 C5 作对照就无法归因。
3b. **A5 走主口径，与 P3-R 不共享协议**：它是时间动力学，与 C5/A4 的关系归纳线互不影响；实现挂在 CSM 树上（已有活动表与衰减），但改的是关系表示入口。**先等 E3/E5 收口**：若「多一条时间尺度/结构专家」在主口径上整体为负，A5 只是把同样的时间信息换个注入位置，应降级；若 E5 的门控成立，A5 是它的天然下一步（把被门控的东西从加项换成表示）。
4. B4 只写设计。
5. 这一层的意义不是「再加一个模块」，而是把论文从「新兴实体预测」扩成**开放词表时序预测**：实体轴已有 EM/AUEM 三 seed 证据，关系轴目前完全空白，2×2 因子表可以成为新的主结果表。

### 18.6 不要做的事

- 不要在现有 transductive 主表上声称关系级归纳（test 只有 22 条 unseen-relation 查询）。
- 不要只报 Rel-Unseen：Rel-Seen 的回归必须同报，否则是「用已见关系的性能换未见关系」。
- 不要把 `base_unk` 当「修好的 base」：它是新协议下的对照，不是主表基线，也不参与 §5 的配对表。
- 不要用时间切分的「关系涌现」作主协议：Q4 只有 8 个关系、每个 1 条事件。

## 附录 D. 分桶重放工具（`_scripts/bucket_ranks.py`，fcs）

不训练、不改 run 目录：加载 `model_*.pth` + `emb_*.pth`，按 `main_enhanced.py` 相同的评测路径把 train/valid/test 顺序前向一遍，记录每条查询的 rank 与当时的 `update_count`。

```sh
python bucket_ranks.py --tree /workspace/01_code/tkgr/adatkg_p1_auem \
  --ckpt <run>/model_seed42.pth --emb <run>/emb_seed42.pth \
  [--prior_grid 0,0.02,0.05,0.1,0.2] --out <json>
```

- `--prior_grid` 是候选侧先验校准诊断：`score − λ·log(1+freq)`，`freq` 只由 train+valid 统计（不看 test）。
- **已知偏差**：重放用 `model.eval()` 预热记忆，没有复现训练期的 `chain_dropout` 写入掩码与优化器轨迹，All MRR 比日志 FINAL 低约 0.014（AUEM seed42：0.3907 vs 0.4044）。桶间比较用它，绝对值不用它。
- **重放噪声底**：同一 checkpoint（AUEM seed42）在 09:03 与 12:03 各重放一次，All MRR 0.3907 vs 0.3894（±0.0013），桶内计数一致。原因未定位（`eval` + `no_grad` 下仍非逐位确定，疑为 GPU 原子加）。因此**桶间比较的噪声底约 ±0.002**；预注册的 `tail_unseen ΔMRR ≥ +0.02` 是它的 10 倍，可用；任何小于 0.002 的桶间差都不算证据。
- 训练脚本自己的 Emerging/Unknown 定义（`get_emerging_index` 随时间推进扩充已知集合、`get_unkown_index`）在这个脚本里被直接调用，不是另写一套。
- **`gold_tail_only` 桶**（2026-11-05 加）：`tail_only_ids` = 在 train+valid 里当过对象、但从没当过头的实体 —— 这正是 AdaTKG-EMA 没有记忆槽的那批（记忆只写给头，E3 的候选读对它们读到空槽）。E3-42 实测桶 `n=1052 / 57200 = 1.84%`，MRR **0.1119** / H@1 **0.0456**。ESM 的主判据落在这个桶上（§14.12）。
- **`by_kind` 四桶**（`tail_seen / head_unseen / both_unseen / tail_unseen`，只在传 `--prior_grid` 时输出）：按「评测当时头/尾是否已见过」分类，用于 TNA 的「两桶同向」判据（§14.14）。E3-42 实测 `head_unseen` n=648 / MRR 0.2466、`tail_unseen` n=573 / MRR 0.1213。
- **配套工具**（都在 `fcs:/workspace/_scripts/`）：
  - `collect_arm.py --runs <dir> --prefix <p> [--ref <dir> --ref-prefix <p>]`：从每个 run 的 `log.txt` 取「`[Valid Emerging]` MRR 最大的那个 epoch」的三行测试快照（= run 自己 best checkpoint 的来源），按**同 seed 配对**输出 Δ。用于收口，不用于桶。已用 E3/AUEM、GLB/AUEM 两对回归校验，与报告里的 Δ 逐位一致。
  - `bucket_diff.py --arm <json> --ref <json> [--set All|Emerging|Unknown]`：两个 replay JSON 的逐桶配对差。**只引用 Δ，不引用绝对水位**（L49）。
